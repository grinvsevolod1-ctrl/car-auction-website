# IGNIS — автоаукцион (Next.js + PostgreSQL + Prisma)

Самодостаточный портал автомобильного аукциона. Работает на любом VPS,
не привязан к внешним сервисам. Своя авторизация (email + пароль, JWT в
httpOnly-cookie, bcrypt), роли пользователей, админка и торги в реальном времени.

## Стек

- **Next.js 16** (App Router, Server Actions)
- **PostgreSQL** + **Prisma 7** (драйвер `pg`)
- **Своя авторизация**: `bcryptjs` + `jose` (JWT), защита маршрутов через `proxy.ts`
- **Tailwind CSS v4**

## Требования

- Node.js 20+
- PostgreSQL 14+
- pnpm (или npm/yarn)

## Установка

1. Скопируйте переменные окружения:

   ```bash
   cp .env.example .env
   ```

   Заполните `.env`:

   ```
   DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/ignis"
   AUTH_SECRET="случайная-строка-минимум-32-символа"
   ```

   Секрет можно сгенерировать: `openssl rand -base64 48`

2. Установите зависимости (заодно сгенерируется Prisma Client):

   ```bash
   pnpm install
   ```

3. Создайте схему БД и наполните начальными данными:

   ```bash
   pnpm db:push      # создать таблицы (или pnpm db:migrate:dev для миграций)
   pnpm db:seed      # создать администратора и демо-лот
   ```

   По умолчанию сид создаёт администратора:

   - **email:** `admin@ignis.by`
   - **пароль:** `admin12345`

   Данные администратора можно переопределить переменными `ADMIN_EMAIL` и
   `ADMIN_PASSWORD` в `.env` перед запуском сида. **Смените пароль после первого входа.**

## Запуск

Разработка:

```bash
pnpm dev
```

Продакшн:

```bash
pnpm build
pnpm start
```

## Деплой на VPS

1. Установите Node.js, pnpm и PostgreSQL, создайте базу данных.
2. Склонируйте проект, задайте `.env` (`DATABASE_URL`, `AUTH_SECRET`).
3. Выполните:

   ```bash
   pnpm install
   pnpm db:migrate      # применить миграции в продакшене
   pnpm db:seed         # (один раз) создать администратора
   pnpm build
   pnpm start           # слушает порт 3000
   ```

4. Настройте reverse-proxy (Nginx/Caddy) на порт 3000 и подключите домен и HTTPS.
   Для автозапуска используйте `pm2`, `systemd` или Docker.

> `AUTH_SECRET` обязателен и должен быть длинным и секретным — на нём подписываются
> сессии. В продакшене cookie автоматически помечается `Secure` (нужен HTTPS).
> Задайте `APP_URL` (например `https://ваш-домен.by`) — он используется для ссылок
> в письмах и проверки Origin при отправке форм.

## Автозакрытие торгов (cron)

Лоты закрываются автоматически при любом обращении к каталогу/лоту (ленивое
закрытие). Чтобы торги закрывались вовремя даже без трафика и победитель
получал уведомление сразу — добавьте cron на VPS:

```bash
# каждую минуту
* * * * * cd /путь/к/проекту && pnpm close-lots >> /var/log/ignis-cron.log 2>&1
```

Скрипт `scripts/close-lots.ts` переводит истёкшие лоты в `SOLD`/`ENDED`,
назначает победителя по высшей ставке и рассылает уведомления.

## Почта (SMTP)

Для писем подтверждения email и уведомлений заполните `SMTP_*` в `.env`.
Если SMTP не настроен, письма выводятся в консоль сервера (режим отладки).
Подтверждение email можно отключить: `REQUIRE_EMAIL_VERIFICATION="false"`.

## Загрузка фотографий

Фото лотов загружаются в админке прямо файлами (drag&drop) — они сохраняются в
`public/uploads`. Для продакшена смонтируйте `public/uploads` на постоянный том,
чтобы файлы переживали пересборку.

## Роли и доступ

- **Гость** — просмотр каталога и карточек лотов.
- **Пользователь** — регистрация обязательна для ставок; личный кабинет со ставками.
- **Администратор** — раздел `/admin`: обзор, CRUD лотов, завершение торгов,
  управление ролями пользователей.

## Структура

```
app/            — страницы (публичные, /account, /admin)
components/     — UI-компоненты
lib/actions/    — серверные экшены (auth, ставки, лоты)
lib/auth/       — JWT, пароли, сессии
lib/            — Prisma-клиент, запросы, форматирование
prisma/         — schema.prisma и seed.ts
proxy.ts        — защита маршрутов /account и /admin
```
